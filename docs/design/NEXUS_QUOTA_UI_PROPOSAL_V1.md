## 列表

每张卡片在状态与创建日期之间增加「当前 30 天配额」：已用/上限、剩余、细进度条、恢复时间。正常为青绿、接近上限为琥珀色、耗尽为低饱和红色，并提供文字，不能仅以颜色区别。
三个演示分别为 350/1000、920/1000、1000/1000；第二个 Application 已禁用但仍能查看配额，第三个仍运行但额度耗尽。应用状态与配额状态是两件事。
卡片说明只使用已有状态文案，不虚构后端不存在的应用简介字段。小图标沿用原设计的装饰角色，不属于应用数据。

## 详情

概览的应用信息卡上方增加配额卡，保留原信息，不增加空标签或一级导航。
配额卡显示 350/1000、剩余650、35%进度、当前周期和北京时间恢复时刻，附「所有 API Key 共用」与执行后失败计次的说明。右上角刷新只重新查询，不重置额度。没有修改配额、购买或升级入口。
周期示例为 2026-10-13 14:00 至 2026-11-12 14:00，恰好720小时。页面称「当前30天」，不称「本月」。

## 实施边界

- 详情可使用新管理接口 `GET /api/application/{applicationId}/quota`，用 Bearer JWT；返回当前 Service 的 `periodStart`、`periodEnd`、`quotaLimit`、`usedCount`、`restCount`。时间字符串按北京时间解释，显示时不得受设备默认时区影响。
- 2026-10-14 后续已补 Application 分页概要：每个记录嵌套 `quota`，字段与详情一致；后端批量查本页各自周期并保序，不逐卡请求详情接口。页面下一步直接使用列表数据。
- 加载期间用局部占位，查询失败显示无法加载/重试，不能把失败显示成已用0。配额0避免除零，展示无可用额度。禁用不阻止所属用户查看，删除仍按不存在处理。
- 窄屏卡片单列，详情指标和周期区堆叠；沿用现有 Element Plus、Scrollbar 和可访问操作要求。Vue 已实现，并通过1440px/390px浏览器检查。
- 「演示数据」只用于视觉评审，运行页面不展示这个标签。

## Vue 接入

列表使用分页记录的 `quota`，详情初次加载复用按 ID 筛选的列表响应；「刷新」只请求单条配额接口。配额独立于应用信息保存在详情页，更新接口不返回 quota 也不会使它丢失。共用展示组件统一计算进度和状态，不在前端计算或重置业务周期。无偏移时间明确解释为北京时间，再以 Asia/Shanghai 格式化。
