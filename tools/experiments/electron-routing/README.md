# Electron 受控转发实验

这是教学用的第一步，不是可部署代理。两个临时 HTTP 服务仅绑定 127.0.0.1，使用随机端口：一个模拟后端，一个同时提供页面和固定路径转发。Electron Renderer 在启用 sandbox、contextIsolation 和关闭 nodeIntegration 下，从转发入口发起同源请求。

使用本地安装的 Electron 45.2.3：在本目录安装后运行 `node_modules/.bin/electron main.cjs`（Windows 可使用 `electron.cmd`）。测试使用模拟凭据，不连接 Nexus 或数据库。窗口隐藏，结束后退出。

初始实验仅检查 GET、凭据、401 和 8 个 PNG 签名字节。扩展结果见下文；本目录仍是教学原型，不是生产代理。

思考：如果页面直接请求模拟后端的不同端口，浏览器为什么可能发起 CORS 检查？该行为跟请求在同一台机器上有什么区别？

2026-11-10 对照结果：CSP 明确允许固定模拟后端地址，直接跨端口请求携带 Authorization 后，后端收到一次 OPTIONS；后端没有给出 CORS 授权，Chromium 拒绝继续，未发送带凭据的直接 GET。经同源入口转发的原有断言继续通过。运行时需允许 Electron 子进程与用户缓存访问；受限执行首次出现缓存拒绝与 GPU 进程失败，在允许的执行环境复验通过，没有关闭 Chromium 的安全配置。

## 扩展实验结果（2026-11-10）

`npm test`：16 个真实 Renderer 检查、7 个原始 HTTP 拒绝检查及模拟后端计数断言通过，进程退出码为 0。没有连接真实 Nexus 或数据库。模拟接口路径仅供实验，不代表真实后端契约。

- POST：方法、UTF-8 JSON、Content-Type、201 状态传递正确；登录不继承 Authorization，后端不收到 Cookie。错误媒体类型、损坏 JSON、超过 4096 字节的请求体分别为 415、400、413；只有有效 POST 到达模拟后端。
- 凭据：Bearer 与 ApiKey 保持调用方提供的类型，错误类型由模拟后端拒绝；401 JSON 完整传回。
- PNG：完整字节一致，Content-Type、Cache-Control、Content-Disposition 保留；Chromium 实际解码为 1x1。初始 Base64 样本无法解码，已改为构造正确 PNG 块和 CRC，未删除解码断言。
- 故障：上游不响应，1500ms 总时限后为 504；连接在响应前断开为 502；响应中途截断使 Renderer 读取失败，不冒充完整下载。
- 重定向：实验策略统一阻止上游 3xx，返回 502，不转交 Location、不跟随跳转，计数确认未访问目标。正式短链 /s 的跳转策略需单独设计。
- 边界：绝对 URL、错误 Host、外部 Origin、cross-site 请求、编码路径、额外查询参数、错误方法被拒绝。上游不存在未知路径命中。目标固定为本机模拟服务，不接受页面提供目标地址。

## 文件与下一检查点

`main.cjs` 是 Electron 启动、模拟后端和断言协调；`gateway.cjs` 是本机转发原型；`renderer-test.js` 在真实 Chromium 页面发起请求。没有 Preload，因为此实验不需要桌面能力桥。

现有证据支持开始正式阶段 1 的最小界面接入，不代表真实后端、Vue 资源与路由、独立构建或生产安全已经验收。正式方案仍须设计入口授权与生命周期、请求体读取时限、响应大小限制、客户端取消、全部真实方法/路径/查询参数和 /s 跳转行为；Host/Origin 检查不等同本机进程身份认证。当前未验证服务完全停止、恶意请求全覆盖或服务器 HTTPS 入口。
