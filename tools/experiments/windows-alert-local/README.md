# Windows 告警状态机本地实验

## 目的

本实验只验证告警判定和重复抑制，不发送邮件、不创建计划任务、不修改 Java、Nginx、80、443 或 8080。生产邮件仍由阿里云云监控发送。

每个检查项使用稳定的去重键：

```text
主机 / 服务 / 故障类型
```

同一次故障从连续失败达到阈值开始，到连续健康达到恢复阈值结束，只使用一个 `incidentId` UUID。`OPEN` 和 `RESOLVED` 通知各有自己的 `eventId` UUID。UUID 用于追踪，不用于判断两个观察结果是否属于同一类故障。

## 状态规则

- 两次失败后恢复：不通知；
- 连续三次失败：写入一次 `OPEN`；
- 故障持续：只更新次数，不重复写入通知；
- 连续两次健康：写入一次 `RESOLVED`，复用原 `incidentId`；
- 故障关闭后再次发生：生成新的 `incidentId`；
- 计划维护：只在事件尚未打开时静默，不能用维护参数掩盖已经打开的故障；
- 并发更新：每个去重键使用独占文件锁；
- 通知采用本地事务式 outbox，进程在写入中途退出后可根据 `eventId` 重试而不重复追加。

## 运行

不需要管理员权限：

```powershell
Set-Location D:\Nexus
& 'C:\Program Files\PowerShell\7\pwsh.exe' -NoProfile -File `
  .\tools\experiments\windows-alert-local\run.ps1
```

每次运行创建独立的 `runtime/<时间-随机值>`，不会覆盖以前证据。重点文件为：

- `state/*.json`：当前检查状态；
- `outbox/notifications.jsonl`：将来交给邮件或云监控适配器的通知；
- `result.txt`：实验断言结果。

`Message` 不得放入数据库密码、JWT、完整凭证或大段原始日志。告警只应包含主机别名、服务名、故障类型、时间、发生次数和安全的错误摘要。

## 2026-10-20 验证结果

一次真实运行验证了：

- 两次失败后恢复，通知数为 0；
- 12 个 PowerShell 7 子进程同时提交失败观察，最终状态累计 12 次，但 outbox 只有一条 `OPEN`；
- 连续两次健康只产生一条 `RESOLVED`，并与 `OPEN` 共用同一个 `incidentId`；
- 五次维护期失败均被抑制；
- 已经打开的 incident 拒绝后来补加的维护静默；
- 后续新故障得到新的 `incidentId`；
- 两次故障合计只有四条通知，四个 `eventId` 均不重复，所有并发子进程 stderr 为 0。

最终复验证据保存在忽略 Git 的 `runtime/20261020-104955-5e2b8eab/`。

## 云服务器上的使用边界

本实验的 outbox 是本地可验证通知出口，不会自己发送邮件。若将来需要真实通知，可以让阿里云云监控直接发送邮件：

1. 在云监控中确认 ECS 的监控插件处于运行状态；
2. 创建并验证报警联系人邮箱；
3. 为公网 HTTPS 可用性创建连续失败规则；
4. 为生产 Nginx 和 Java 创建进程数规则；
5. 订阅 ECS 停止、重启等系统事件；
6. 设置连续周期和通知抑制后做一次受控故障与恢复测试。

云监控负责“从服务器外还能否看到服务”，本地 WinSW/监督进程日志负责解释“为什么退出、是否恢复、清理了哪个 PID”。2026-10-20 决定当前不承担外部告警成本，因此不配置真实云监控联系人、规则或邮件，也不把本地 outbox 上报为云监控自定义事件；实验代码只保留为学习和以后可选的恢复点。
