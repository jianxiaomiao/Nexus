# IP-6：可信名单、递归方向与停止边界

日期：2026-10-14。一个启动对照和四个实验GET请求均成功，Java收到的有效地址以及Nginx日志中的原始对端、有效地址均符合预测。本轮只使用18080/18081回环实验端口，不连接数据库，不修改日常入口或业务后端。

## 术语

- `$realip_remote_addr:$realip_remote_port`：realip替换前，当前这段TCP连接的直接对端。
- `$remote_addr:$remote_port`：realip处理后，当前请求使用的有效客户端地址。没有发生替换时，它就是直接对端。
- `connectionPeer`、`effectiveIp`：实验日志中为上述变量起的标签，不是Nginx指令。

`$realip_remote_addr`不是“最初用户到系统的端到端地址”。每个代理只能直接验证与自己建立连接的上一跳。

## 固定输入链

四组请求都携带同一条诊断链：

```text
X-Forwarded-For: 203.0.113.7, 192.0.2.10, 198.51.100.20
```

为了理解顺序，可以暂时标成：

```text
较远                                                         较近
203.0.113.7  <-  192.0.2.10  <-  198.51.100.20  <-  当前Nginx
```

这些是文档保留地址，只用于实验，不证明请求真的经过这些节点。

递归解析不是简单取最左项。Nginx先验证实际TCP对端是否可信；可信后，从XFF右侧向左跨过可信地址，在第一个非可信地址处停止。官方表述是选择请求头中最后一个非可信地址。

## 四组变量

### 1. 递归开启，较窄可信名单

```nginx
set_real_ip_from 127.0.0.1;
set_real_ip_from 198.51.100.20;
real_ip_recursive on;
```

实际对端127.0.0.1可信；XFF最右侧198.51.100.20可信；再向左的192.0.2.10不可信，因此停止：

```text
$remote_addr = 192.0.2.10
```

更左侧的203.0.113.7不能穿过这个不可信边界影响结果。

### 2. 递归开启，扩大可信名单

在同一名单增加：

```nginx
set_real_ip_from 192.0.2.10;
```

现在解析可以继续越过192.0.2.10，停在203.0.113.7：

```text
$remote_addr = 203.0.113.7
```

扩大信任会改变身份结果，因此可信代理名单必须来自真实、受控的部署拓扑。

### 3. 关闭递归

直接对端127.0.0.1可信，但：

```nginx
real_ip_recursive off;
```

Nginx使用请求头最后一个地址，不继续遍历中间代理：

```text
$remote_addr = 198.51.100.20
```

### 4. 直接对端不可信

请求通过IPv6回环 `::1` 连接，而该地址不在此location的 `set_real_ip_from` 中。即使头内容与前三组完全相同，也不用于替换：

```text
$realip_remote_addr = ::1
$remote_addr = ::1
$remote_port = 57019
```

这一步是信任模型的入口：先验证谁实际连接了Nginx，再考虑其提供的头。

## 实际结果

| 场景 | 原始直接对端 | 有效IP | Java收到的XFF |
| --- | --- | --- | --- |
| 递归，窄名单 | 127.0.0.1:65479 | 192.0.2.10 | 192.0.2.10 |
| 递归，扩展名单 | 127.0.0.1:57015 | 203.0.113.7 | 203.0.113.7 |
| 非递归 | 127.0.0.1:57017 | 198.51.100.20 | 198.51.100.20 |
| 不可信IPv6直接对端 | [::1]:57019 | ::1 | ::1 |

Java仍由Nginx通过IPv4连接，四组Java peer均为动态的 `127.0.0.1:端口`，local均为 `127.0.0.1:18081`。Nginx通过 `proxy_set_header` 将解析后的有效IP写给Java；Java原始TCP peer不会变成该IP。

当地址来自不含端口的XFF时，有效端口为空；未发生替换的第四组仍保留真实连接端口57019。动态端口在重跑时会变化。

## 运行

从 `D:/Nexus` 的PowerShell执行：

```powershell
& .\tools\experiments\ip-6\run.ps1
```

脚本复用IP-1的启动与清理流程，对每组Java输出和Nginx日志执行预期值检查。日志使用 `escape=json`，避免把收到的头原样写入日志格式控制字符。本实验仍将127.0.0.1作为模拟可信来源；这会信任所有能以该地址直连的本机进程，不是生产进程身份认证。
