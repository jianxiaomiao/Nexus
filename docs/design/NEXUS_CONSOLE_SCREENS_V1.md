## 共用布局

- 左侧导航、顶部上下文和主内容区保持一致；小屏改为紧凑导航。当前导航只放已经可用的 Application 页面，不加空的“设置/统计”入口。
- 暖白纸面、浅鼠尾草绿导航区、青绿色主操作、深墨绿正文、少量金色星星；卡片用细边框和极轻阴影。绘本元素主要用于空状态，数据卡片保持克制。
- 列表中名称优先，状态要有文字；内部 ID 不外显。列表和详情不显示尚未由接口提供的 Key 数量、调用量、描述等字段。
- 创建、改名使用弹窗；禁用说明会影响 API Key 调用；删除要求输入应用名称。危险确认保持简洁严肃。
- 两种详情页右上角都按「编辑、禁用/启用、删除」从左到右排列三个独立图标按钮。视觉稿省略文字不等于实现可省略语义：按钮需要悬停/聚焦提示、可访问名称、键盘焦点样式和至少 44×44 px 的触控目标；警告与危险不能只靠颜色区别。禁用状态下第二个按钮应变为“启用”。窄屏可让整组操作换行，不压缩触控区域。
- 删除始终二次确认；Application 删除按名称输入确认，API Key 删除使用明确的强确认。禁用 Application 前说明其 API Key 将无法调用；禁用 Key 使用较轻确认。图标点击本身不直接执行危险操作。

## 实现边界与待确认点

- “首页”指登录后 Application 列表的空状态，不新增独立首页或没有数据支撑的统计面板。
- 列表选定版只对原始稿去掉了“个人设置”。用户认可卡片本身的构图与装饰；卡片简介及独立装饰图标是视觉样例，当前后端没有对应描述或图标字段，不应伪造为真实数据。
- 列表 V2 曾尝试重排卡片，未获用户认可，不作为实现基准。
- “已禁用”状态的具体颜色遵循设计规范的警告/禁用语义，不与删除/错误的红色混淆。
- 页面图标使用 [最小图标集](NEXUS_ICON_SET.md)；图像稿中的字符形状不是最终 SVG 规格。
- [Application 详情上一版](NEXUS_APPLICATION_DETAIL_REVISED_V2.png)和 [API Key 详情上一版](NEXUS_API_KEY_DETAIL_V1.png)保留作演进记录；当前待审视觉稿以表格中的图标操作新版为准，API Key 详情底部不再另设重复的删除区。
- 原 [Application 详情旧稿](NEXUS_APPLICATION_DETAIL_V1.png) 同时放了 `API Keys` Tab 和底部“查看 API Keys”卡片，属于重复入口；当前前端只保留已接入真实列表接口的 Tab。
- API Key 详情稿只使用现有列表响应可提供的字段；内部数据库 `id` 不外显，图片里的名称、Public ID、遮蔽预览和时间均为虚构样例。完整 Key 只在创建响应中出现一次，详情页不能展示、复制或找回它；图中也不应出现调用量、最近使用时间和过期时间等当前没有的数据。
- 后端尚无单个 Key 的查询接口。当前详情页刷新及深链接通过先读取当前用户的 Application 列表、再读取所属应用的 Key 列表并按内部 `id` 查找；无权或已删除时显示不可访问状态。
- 生成图片里的时间、应用名称只是示例。界面以真实 API 数据填充；图中英文或不准确的文案以项目实际中文文案为准。

## 生成用视觉提示词摘要

工具：内置 imagegen；用途分类：`ui-mockup`。三张图均要求 16:9、平面桌面 Web UI、高保真但可实现、非设备透视图，无水印。

1. 首页/空状态：Nexus 共用侧栏和顶栏，主区域是 Applications 标题、创建操作及居中的首次创建引导；小幅原创橘白猫坐在鼠尾草绿星球上，星星点缀；无图表、计数、密钥。
2. Application 列表：同一视觉系统，三个示例应用卡片；名称、文字状态、创建时间、查看详情和更多操作；无内部 ID、统计指标、Key 数量。
3. Application 详情：以内置 imagegen 编辑旧稿，先删除重复的底部 API Keys 卡片和生成失真的副标题，再把右上角文字操作改为编辑、禁用、删除三个方形图标；只留下未来的 `API Keys` Tab，不展示真实 Secret 或虚构统计。
4. API Key 详情：以内置 imagegen 新生成并做导航修订，单卡呈现现有响应字段；再把右上角文字操作改为同一组三个图标，并移除底部重复的删除区；绝不展示完整 Key、Secret Hash、虚构使用统计或未实现的导航。
