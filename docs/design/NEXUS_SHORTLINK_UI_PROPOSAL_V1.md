## 页面与身份

1. 调试台在 UUID、Hash 旁增加「短链接」，内部提供创建、查询列表、修改、删除四个操作。机器请求只带用户临时输入的完整 API Key；Key 不进路由、示例、持久化存储或日志。创建表单包含名称、原始 HTTPS 地址和有效期；在**提交时**把预设时长换算为带时区的绝对到期时刻。10～30 秒选项提示首次访问可能赶不上到期。
2. 创建成功后，响应区先给出可复制的完整短地址，再展示名称、目标、到期时刻和所属 Key。点击「管理这把 Key 的短链」进入按 `apiKeyId` 筛选的管理页；该页仍必须通过当前 JWT 验证所有权。响应区不能仅因机器 Key 有效就假定登录用户拥有它。
3. 控制台侧栏增加「短链接」管理入口。页面先选 Application，再选 API Key；列表只展示选中 Key 的未删除短链。API Key 详情页也可跳到同一管理页并预选 Key。列表提供复制、改名、禁用/启用和删除。状态按后端跳转判定顺序展示：短链自身禁用、父级禁用、到期；父 Application 或 Key 禁用时提示“上层已禁用”，不改写短链自身状态。
4. 管理页使用 Bearer JWT 调用 `/api/short-links`；「创建短链」前往调试台，使用 API Key 调用 `/v1/short-links`。当前后端没有 JWT 创建短链接口，不在视觉稿中虚构该能力。公开 `/s/{shortCode}` 不带任何凭证。
5. 文档的「API 参考」增加一篇「短链接」，介绍创建字段、机器端四种操作、JWT 管理、公开跳转、精确主机名白名单、过期边界及错误响应。文档首页的“两项开放能力”文案应同步更新。

## 地址与视觉规则

- 图片中的 `nexus.example` 是**示意域名**，不能作为运行时常量。正式短地址应由受配置的公开地址与服务器返回的 `shortCode` 组合。本地开发需要把 `/s/*` 转发给后端；部署时由公开入口负责同一路径。
- 只接受 HTTPS 与后端规定的精确主机名。界面提示这项检查不证明网页内容安全。原始 URL 创建后不可修改，列表中的操作不出现“更改目标”。
- 沿用现有暖白背景、浅鼠尾草绿侧栏、青绿主按钮、深绿代码块和少量金色装饰。桌面管理页使用表格，手机端变为记录卡片；状态同时使用文字与颜色。
- 删除需确认；列表刷新后不再显示已软删除记录。短码永久不复用。短链到期后记录仍可查看和删除，启用按钮不应暗示可以恢复跳转。

## 接入时的重点验收

- 创建成功立即复制短地址，刷新后可从同一 Key 的管理列表找回；切换到另一把 Key 不应显示这条记录。
- 有效短链公开访问得到 302；禁用或删除后不可跳转；到期瞬间不可跳转。页面状态与后端真实响应保持一致。
- 调试台不把完整 Key 带到管理路由或复制示例；管理页 JWT 不参与 `/v1/*` 机器请求。
- 小屏幕上的长 URL、状态文字和操作按钮仍可阅读、点击；空列表、加载失败及无权访问都有明确反馈。
