# Nexus API 调试台视觉提案 v1

状态：**页面已按视觉稿实现，开发者于 2026-10-06 确认 UUID/Hash 真实调用成功**；完整 Key 状态生命周期仍需单独验收。桌面稿：[请求与响应双栏](NEXUS_API_PLAYGROUND_DESKTOP_V1.png)；手机稿：[纵向排列](NEXUS_API_PLAYGROUND_MOBILE_V1.png)。图片用于确认布局和视觉层级，字段、文案和示例的最终依据是 [`docs/OPEN_API.md`](../OPEN_API.md) 与后端实现。

## 页面与交互

- 控制台侧栏增加“API 调试台”入口；开发文档首页和 API 文章提供跳转入口。一个 `/playground` 页面切换“生成 UUID”和“计算 Hash”，文档跳转可预选接口，但 URL 不携带 API Key。
- 桌面端上方选择接口，下方左侧填写请求、右侧查看**实际** HTTP 状态、耗时和 JSON 响应；再下方显示独立的 curl / PowerShell 请求示例。手机端依次排列选择器、请求、响应和可折叠示例，导航收起。
- API Key 由用户手动输入，只在当前页面内存中使用；不持久化、不写日志、不放 URL、不进入请求历史。示例只能显示占位符，不能把用户填写的 Key 拼进可复制示例。页面离开时清除 Key。
- Hash 表单选择 `SHA256` / `SHA512`，填写 `value`，按 UTF-8 **字节数**显示 `当前 / 4096`。`value` 允许空字符串；不要把密码或完整 API Key 当作 Hash 输入示例。
- 调试请求仅使用现有 `GET /v1/utils/uuid` 和 `POST /v1/utils/hash`；机器认证是 `Authorization: ApiKey <完整密钥>`，与管理 API 的 Bearer JWT 分开。前端开发环境通过代理转发 `/v1/*`，浏览器按同源路径调用；不开放任意 URL 或自定义 Header 编辑器。
- 未发送、发送中、成功、400、401、403 和网络失败应各有明确状态。失败时保留可安全展示的状态码、业务错误码和消息，响应区不要假造成功结果；重试由用户主动触发。

## 视觉边界

沿用暖白纸面、浅鼠尾草绿、深墨绿、青绿色主操作和少量金色手绘星星。装饰不进入输入与响应的阅读区域。代码与技术值使用等宽字体，状态不只靠颜色表达；复制、切换、折叠和发送控件保留可访问名称。图中 `hello`、`200 OK`、`128 ms` 和响应 JSON 是**静态示意**，运行时以真实请求为准。

两图由内置 imagegen 以 `ui-mockup` 模式生成并定向校正。提示词重点：桌面双栏、手机纵向、Nexus 既有配色与留白、当前两条 Open API、正确的 `ApiKey` 认证及 `algorithm`/`value` 请求字段、密钥不持久化。未使用真实凭证。
