# Nexus 开发文档页面提案 v1

状态：首页与文章阅读界面已按此提案实现。当前 `/docs` 和 `/docs/:slug` 与控制台一样要求登录；开放文档是否允许匿名阅读留待单独讨论。API 字段、状态码与示例以 [`docs/OPEN_API.md`](../OPEN_API.md) 和实际后端契约为准。

## 页面结构

文档采用独立的阅读布局：顶部保留 Nexus 品牌和“返回控制台”，左侧是文档目录，右侧是列表或文章。不要同时显示控制台侧栏和文档侧栏，以免两套导航争夺宽度。文档入口仍可从控制台进入；是否允许未登录访问留到路由设计时确认。

首页只提供当前真实能力所需的五篇文档，不模仿大型云平台的多层分类：

| 分组 | 文档 | 核心问题 |
| --- | --- | --- |
| 开始使用 | 快速开始 | 如何创建 Application、创建 API Key 并发送第一条请求？ |
| 开始使用 | API Key 与认证 | 完整 Key 何时可见？`ApiKey` 与 `Bearer` 如何区分？ |
| API 参考 | 生成 UUID | `GET /v1/utils/uuid` 如何调用、返回什么？ |
| API 参考 | 计算 Hash | `POST /v1/utils/hash` 的参数、字节限制与响应是什么？ |
| 帮助 | 错误码与排查 | 401、403、请求体验证错误分别如何处理？ |

首页以“第一条调用”为主线：简短介绍、三步引导、五篇文档卡片。没有足够内容支撑站内搜索、复杂分类、统计卡片或无功能入口时，第一版不展示它们。卡片点击后进入独立文档详情，不在首页展开整篇文章。

## 详情页模板

- 顶部：面包屑、文档标题、简短用途说明；API 参考页显示 HTTP 方法与路径。
- 正文：认证说明、请求参数、可复制的请求示例、成功响应、错误说明；只显示当前接口真正存在的字段。
- 右侧：当前文章的页内目录，随滚动高亮当前章节；小屏幕移到正文顶部的折叠目录或隐藏，不挤压文章。
- 底部：上一篇/下一篇及返回文档首页，帮助用户继续阅读。
- 代码区使用等宽字体，窄屏允许横向滚动；复制按钮需有文字提示及键盘可访问名称。正文和表格保持可读宽度，不靠插图承载技术信息。

Hash 详情图用于展示模板，不是最终内容截图。实际文档必须补充：`algorithm` 只接受 `SHA256`/`SHA512`；`value` 字段必填但允许空字符串；限制按 UTF-8 **字节数**计算，上限 4096；成功体字段为 `data.hashContent`；错误码遵循现有契约。完整 API Key 仅用占位符示意，任何示例都不包含真实凭证或密码。

## 视觉原则与待定边界

沿用控制台的暖白纸面、浅鼠尾草绿、深墨绿、青绿色强调和少量金色星星。首页可有极淡的手绘星球装饰；详情页以文字、参数表和代码为主。图标与装饰不是新的业务能力。移动端将左侧目录收为可打开的导航，保留面包屑、文章标题与代码阅读能力。
