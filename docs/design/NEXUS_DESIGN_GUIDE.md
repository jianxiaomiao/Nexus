# Nexus 前端设计规范 v1

状态：第一版视觉与 Web 控制台范围已确认；后续按真实页面和用户反馈调整。Web、小程序和 App 共享业务与品牌语义，各自适配布局和控件。

## 1. 产品和体验

- 当前优先服务个人学习与使用场景中的开发者。第一版先做 Web Developer Console；普通用户产品以后单独设计。
- 控制台的主要任务：管理 Application 和 API Key，查阅开放 API 的调用方法，查看调用统计，调试开放 API。
- 体验关键词：专业、可靠、简洁、友好，并保留年轻、温暖的品牌气质。信息组织参考高效的开发者控制台；功能区保持清楚、稳定、易读。
- 视觉概念：暖白纸张上的小型星球世界。手绘插图承载品牌氛围，操作控件保持规整。参考图片只作为质感与氛围参考，不复制其中的角色、构图或标识。

## 2. 跨端共享与适配

跨端共享业务术语、状态含义、品牌色的语义、错误与反馈原则、敏感信息规则。各端可以用不同布局完成相同核心任务：Web 可使用宽屏卡片和表格，小程序与 App 使用适合触摸的导航和列表。移动端允许将高级统计与调试能力安排在后续阶段。

第一版先验证 Web；小程序与 App 未来使用同一个 Nexus 账号，并在各自平台适配核心业务能力。普通用户产品与开发者控制台分开规划。

## 3. 品牌视觉

- 页面以暖白为主，浅鼠尾草绿用于少量背景装饰或辅助区域。纸张纹理非常淡，不干扰文字。
- 主操作、链接和当前导航使用青绿色；深墨绿用于重要文字；金黄色用于星星等少量品牌点缀。
- 成功、警告/禁用、危险/删除、不可用/已删除使用各自独立的语义色；状态同时提供文字，不能只靠颜色表达。
- 插图采用彩色铅笔质感，局部可用清楚的深色线稿。元素可包含星星、星球、月亮、植物、花朵、云、山丘和小岛。插图之间有轻微故事关联，无需强制形成完整剧情。
- 原创吉祥物方向：矮胖、可爱的黄白色橘猫。可出现在登录页、空状态和引导中。造型、服饰和场景须原创。
- 目前使用 `Nexus` 文字标识，图形 Logo 待品牌方向稳定后设计。
- 橘猫在第一版登录页使用较完整的插图，在空状态使用简化小插图；一次性 Key 展示可使用小型手绘星星或钥匙。表格、表单与删除确认保持清晰。功能卡片只使用极小的星星、轨道或节点装饰。

当前认可的配色方向以视觉预览为准。Web 的首批语义色候选值如下，实施时须检查文字和控件的可读性：

| 语义 | 候选值 | 用途 |
| --- | --- | --- |
| 纸张背景 | `#FAF9F4` | 页面底色 |
| 浅鼠尾草绿 | `#EEF2E8` | 局部背景与品牌区 |
| 内容表面 | `#FFFEFB` | 卡片、表单区 |
| 深墨绿 | `#203B37` | 标题与主要文字 |
| 青绿色 | `#247B70` | 主操作、链接、当前导航 |
| 金黄色 | `#E7BD58` | 少量星星点缀 |

成功、警告、危险和禁用应使用独立的语义 token；不能把青绿色主操作色直接当成成功状态色。深色主题只预留语义，不在第一版实现。

## 4. 基础视觉与交互

- 信息密度适中；标题和正文清晰、现代；圆角中等；卡片和弹窗使用细边框与轻阴影。
- API Key、URL、代码及公开 ID 使用等宽字体；其余内容使用易读的界面字体。具体字体、字号、颜色值和响应式断点待页面样例确认。
- 图标只在帮助识别操作时使用；动画短而轻，用于说明状态变化。
- Application 与 API Key 详情页可用右上角的图标按钮组呈现编辑、禁用/启用、删除。纯图标按钮必须有可访问名称、悬停及键盘聚焦提示、清晰焦点态和至少 44×44 px 的触控区域；危险操作仍经过确认，不能只靠图标形状或颜色传达含义。
- 表单在离开字段后显示该字段错误，提交时检查全部字段。普通操作成功显示短暂反馈并留在当前页面。
- 页面加载失败时显示原位错误与重试；普通操作失败显示明确提示。按钮操作显示局部加载，列表显示局部加载或骨架；空列表显示简洁插图/图标、说明及主操作。
- 错误先用易懂语言说明问题和恢复方式，再在辅助位置显示业务错误码。日期列表显示简洁时间，详情显示完整时间。
- Web 的主要操作应能通过键盘完成。中文为第一版语言；文案应便于以后国际化。

## 5. Web Developer Console

- 登录后直接进入 Application 列表。可收起的左侧导航第一版只放 `Application` 和 `API 文档`；API Key 从 Application 详情进入。顶部显示当前标题或面包屑，以及用户菜单；深色模式和通知入口在对应功能存在时加入。浅色主题先落地，Design Tokens 为未来深色主题保留语义。
- 列表内容可随屏幕展开；表单与详情正文限制最大宽度。手机浏览器保证基本可用，复杂管理优先在桌面完成。
- 登录/注册页使用左侧品牌介绍约 40%、右侧表单约 60% 的桌面布局。品牌区有插图；文案包含明确的产品说明与温暖副标题。窄屏布局待设计。
- Application 列表第一版使用卡片，之后按实际信息量决定是否增加表格切换。卡片展示名称、状态和必要的时间信息，不显示 ID。当前列表接口提供的内部 `id` 保留在 TypeScript 数据模型中，用于路由与后续 API 操作。ID 不属于机密；页面不展示是信息层级选择。手机浏览器中“查看”和“创建”保持显眼，“编辑”“禁用”“删除”收进“更多”菜单。
- Application 使用独立详情页。创建与编辑在字段少时使用弹窗；复杂设置进入页面。禁用前说明它会影响 API Key 调用；删除要求输入 Application 名称确认。
- API Key 在 Application 详情页的独立标签中管理，桌面列表使用表格；单个 Key 的详情可从该列表进入，不在 Application 概览中再放一个重复入口。创建成功后弹窗展示完整 Key 一次，突出复制和保存；关闭前勾选“我已经保存”。复制后按钮短暂显示“已复制”，并给出轻量提示。
- 禁用 Key 使用较轻确认；删除 Key 使用较强确认。删除对话框保持严肃，不放插图。API Key 列表只显示预览值，不再次显示完整 Secret。
- `API 文档` 是控制台内的页面，由 Nexus 自己呈现开放 API 概览、认证方式、UUID/Hash 接口、请求示例、响应示例和常见错误。示例使用占位 Key，不含真实 Secret。文档内容以实际 HTTP 契约和 `docs/OPEN_API.md` 为依据，避免两处描述不一致。网页内调试工具留待明确需求后设计。调用统计尚无后端接口，第一版不放无功能的导航占位。

## 6. Web 实现边界

Element Plus 计划在 `nexus-console` 全量引入，作为表单、按钮、表格、弹窗等 Web 控件的实现。Nexus 自己定义语义 Design Tokens，再映射到 Element Plus 主题变量。业务状态、页面结构、文案和插图属于 Nexus 设计规范。

不要把某个 Element Plus 组件的默认颜色或样式当作跨端规范。仅在真实页面反复使用时提取 Nexus 业务组件。

已认可的设计方向预览见 [NEXUS_VISUAL_PREVIEW.html](NEXUS_VISUAL_PREVIEW.html)，截图见 [NEXUS_VISUAL_PREVIEW.png](NEXUS_VISUAL_PREVIEW.png)。插图仍是概念稿，不是最终 Logo 或吉祥物定稿。

## 7. 后续按需细化

- Application 详情页先按业务需要规划概览、API Key 和设置；真实内容确定后再固定标签，不增加空标签。
- Key 数量和调用量不在当前 Application 列表响应中；需要时设计对应后端契约，不由列表逐项请求来凑数据。
- 等调用统计有后端能力时再设计统计入口；网页内调试工具需先决定 Key 的输入和存储边界。
- 吉祥物名称可延后确定。响应式断点、字体与状态色以实际页面的可读性和交互测试为准。
